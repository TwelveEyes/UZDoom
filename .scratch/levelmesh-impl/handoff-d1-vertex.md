## Objects created
Per `FGLLevelMesh` (one global per GL frame buffer):
- `GLVertexBuffer mVertexPool` — the 32-byte vertex pool, ONE `glBufferData`
  (`GL_STATIC_DRAW`) at level load via `SetData(size, data, BufferUsageType::Static)`.
- `TArray<std::unique_ptr<GLIndexBuffer>> mRegionIBOs` — one IBO per region
  (`FLevelMesh::regionIBOs[r]`, `uint32` indices, `GL_STATIC_DRAW`).
- `TArray<unsigned int> mVAOs` — one VAO per region. Each VAO captures: the
  vertex pool bindings (table below) + the region IBO on
  `GL_ELEMENT_ARRAY_BUFFER`. (A region's `LevelMeshRegion::iboOffset/iboCount`
  sub-range is a byte offset for `glDrawElements`, not a separate VAO.)

## Attribute / buffer layout (stride 32, `levelmesh::LevelMeshVertex`)
Locations are the fixed `VATTR_*` indices (buffers.h), matching the
`layout(location=N)` inputs generated by
`ShaderInputsOutputs::GenerateInputsOutputs` (hw_shaderpatcher.cpp) and the
ATTRIBUTE MAPPING comment at the top of `wadsrc/static/shaders/glsl/levelmesh.vp`.

| location | attribute   | GL type       | byte offset | C++ field (32-byte vertex) |
|---------:|:------------|:--------------|------------:|:---------------------------|
| 0        | aPosition   | GL_FLOAT × 3  | 0           | x, y, slotA                |
| 1        | aTexCoord   | GL_FLOAT × 2  | 16          | u, slotB                   |
| 6        | aLightmap   | GL_FLOAT × 3  | 20          | lmu, lmv, float(surfaceIndex) |
| 4        | aNormal     | UNBOUND       | —           | (no normal in the 32-byte vertex) |

- `aNormal` (VATTR_NORMAL) is deliberately left unbound: the 32-byte pool has
  no normal field, and an unbound attribute reads as (0,0,0,1). `levelmesh.fp:410`
  guards `dot(vWorldNormal, vWorldNormal) > 0.5` and takes the no-normal
  fallback branch, so draws are deterministic. **Chunk E/F must derive the
  per-surface normal in the VS from the plane records (or extend the vertex)
  before normal-based shading is A/B-validated** — flagged as residual risk.
- `aLightmap.z` carries `float(surfaceIndex)` as a VALUE, not the raw uint32
  bit pattern: GLSL 330 has no float→uint bit-cast and the VS recovers the
  index with `int(aLightmap.z)`; raw bits would decode to ~0 for small
  indices. Float values are exact for indices < 2^24.
- `aColor` (2), `aVertex2` (3), `aNormal2` (5), `aBoneWeight` (7),
  `aBoneSelector` (8) are not enabled in the VAOs.

## VBO repack (IMPORTANT for D2/E)
`mGpuPool` (CPU copy kept by the class) is the pool repacked for the GL
layout: bytes 0..27 are identical to `FLevelMesh::vertices`, byte 28 is
`float(surfaceIndex)` instead of the raw `uint32`. The repack is a one-shot
CPU copy at level load; `FLevelMesh::vertices` stays canonical (the raytrace
adapter `doom_levelmesh.cpp:42` still reads the raw uint32 from it). Any
later re-upload (dynamic-surface spans, ticket 05) must go through the same
repack.

## Object lifetimes
- `GLLevelMesh` global: created in `OpenGLFrameBuffer::InitializeState`,
  deleted in `~OpenGLFrameBuffer` (i.e. on video mode change, together with
  the whole GL context state).
- VBO/IBOs/VAOs: built at level load (`MapLoader::LoadLevel` →
  `screen->SetLevelMeshData(levelMeshData)`), destroyed at level unload
  (`FLevelLocals::ClearLevelData` → `SetLevelMeshData(nullptr)`). `Destroy()`
  rebinds `GLRenderer->mVAOID` first (a VAO cannot be deleted while current);
  VAO creation also restores `mVAOID` afterwards, so the renderer's default
  VAO attribute state is never touched.
- `SetMesh(mesh)` is a no-op when `mesh == mMesh`, so it is safe to call
  every frame — Chunk E should call it at the frame-build site to re-sync
  after a video mode change (context recreation leaves the global empty).

## API Chunk E calls
```cpp
#include "gl_levelmesh.h"   // namespace OpenGLRenderer

FGLLevelMesh *GLLevelMesh;              // null-safe global (screen's)
void   FGLLevelMesh::SetMesh(const levelmesh::FLevelMesh *mesh); // re-sync; no-op if current
bool   FGLLevelMesh::IsReady() const;   // false until a model is uploaded
size_t FGLLevelMesh::RegionCount() const;
const levelmesh::FLevelMesh *FGLLevelMesh::GetMesh() const; // model these objects were built from
size_t FGLLevelMesh::VertexCount() const; // elements in the pool VBO
unsigned int FGLLevelMesh::GetVAO(size_t region) const; // 0 .. RegionCount()-1
```
Draw a region sub-range: `glBindVertexArray(GLLevelMesh->GetVAO(r));`
`glDrawElements(GL_TRIANGLES, iboCount*3, GL_UNSIGNED_INT, (void*)(uintptr_t)(iboOffset*4));`
(`iboOffset`/`iboCount` come from `FLevelMesh::regions[r]` / the sub-range
table; index size is always 4). The classic renderer's default VAO
(`GLRenderer->mVAOID`) stays the engine default for everything else.

## GL constraints hit
- VAOs are GL 3.0+ core; the backend already requires 3.3 core (compiles
  330-core, `glGenVertexArrays` already used by `FGLRenderer`). No extension
  needed.
- `GLVertexBuffer::Bind(int*)` hides `GLBuffer::Bind()` and would reset all
  attribute pointers, so the pool bind uses `static_cast<GLBuffer&>(...).Bind()`.
- `SetData` is protected on `GLBuffer` (hidden); uploads go through the
  `IVertexBuffer`/`IIndexBuffer` interface references, as the existing code does.

## Residual risks / notes for later chunks
1. aNormal unbound (see table) — normal-based shading in `material_normal.fp`
   runs in the fallback branch until E/F provides real normals.
2. `GLLevelMesh` is a single slot: with multiple levels co-resident (portal
   WADs) the most recently loaded level owns the objects; E's per-frame
   `SetMesh(Level->levelMeshData)` re-syncs on level switch (rebuild cost =
   one upload). Ticket 03 is non-portal only, so this is acceptable; a
   per-level object map would be the generalization.
3. GL context is assumed current at the maploader/p_setup hook sites — true
   for the single-context SDL path, and the maploader site already does GL
   work (`InitLightmap`).
4. `GLBuffer::SetData(0, ...)` is legal but a zero-vertex pool yields
   `IsReady()==false`; E should skip the levelmesh pass in that case.
