## 2. Section 10 — classic-path baseline + bars (ticket 10)

Ticket 10 (task, resolved 2026-10-06) ran the classic-path baseline on §9's 26 maps. The kit used **EXISTS on disk today** under `tools/abtest/`; it is NOT the §9 A/B capture mode + `tools/abtest.py` (built by the implementation effort — see §4/§11 "Distinction").

**Reference machine (dev box = reference; recorded 2026-10-04).** Void Linux, kernel 7.2.9_1, Wayland session (display in-session); AMD Ryzen 9 5900X 12C/24T (~4.95 GHz max); AMD Navi 31 (PCI 1002:744c, RX 7900 class), amdgpu + Mesa; 31 GiB RAM; RelWithDebInfo; framebuffer pinned host-native 2560×1440 (DP-1 panel; a 1920×1080 panel is also connected — virtual desktop 4480×1440), vsync off; real-GPU drivers verified per run — GL: `radeonsi, navi31, ACO`; Vulkan: `RADV NAVI31` (discrete).

**Protocol.** 26 maps × {GL33, Vulkan} = 52 runs, each a fresh level load, driven by `tools/abtest/run_matrix.sh` (sequential; writes `logs/status.tsv`; per-run stdout checks). Demos: the 26 SYNTHETIC demos in `tools/abtest/demos/` — `make_demo.py` computes a seeded travel-to-spiral camera from each map's real geometry + the engine's exact tic model and packs a valid UZDoom `.lmp` (fixed seed, demo_version 114, demo_compression, -nomonsters-compatible, noclip2, 2600 tics); deterministic — replays frame-identically across code changes except where a map's scripted events diverge the sim (detectable from the perflog `L` line); all 26 replay-verified 2026-10-05 (full 2600 tics, exit 255, `L` lines match pins). Settings: 2560×1440 via `-width`/`-height` FARGs (`vid_width`/`vid_height` are not cvars in this engine), `-nomonsters` every run, `baseline.cfg` pins (gamma 1.0 = `vid_fixgamma 0`/`vid_contrast 1`/`vid_saturation 1`, vsync off, `vid_maxfps 0`), `vid_preferbackend` set explicitly per run (0=GL33, 1=Vulkan; the engine auto-selects at startup — no `gl_backend` cvar). Resolution axis dropped 2026-10-05: calibration on DOOM2_MAP01 (GL33, 2600 tics) showed identical per-frame cost at 320×200 / 1920×1080 / 3440×1440 (med ≈ 0.235 ms, p95 ≈ 0.26 ms, max ≈ 6.6 ms — 2.4× pixels, zero cost delta): timedemo is CPU-bound (scene graph / draw-call side) at that scene size. PWAD mount: the four non-commercial WADs (myhouse, Pirates!, planisf2, SOS_Boom) mount on the commercial base (`-iwad wads/DOOM2.WAD -file wads/<pwad>`); a bare `-iwad <pwad>` aborts before the demo loads (exit 0, silent); the three commercial IWADs run standalone — encoded in `run_matrix.sh`'s `mount_for`. Real GPU only: a sandboxed shell blocks `/dev/dri` and the engine SILENTLY renders with llvmpipe (software GL; Vulkan finds no ICD and falls back to GL) while still exiting 255 with a full perflog — `run_matrix.sh` rejects any run whose stdout shows llvmpipe or a failed Vulkan init; the matrix ran unsandboxed. Completion check: timedemo exits 255 on success (I_FatalError-style); `F <frame>` numbers the rendered frame (uncapped, 40k–160k per run; ~80–90 s per run regardless of map size; full matrix ≈ 75 min) and `tic=` carries the demo tick; a run is accepted only if the perflog exists and the last `F` line's `tic=` ≥ 2599 (no "F 2600" summary line; `grep '^F 2600'` also matches `F 2600x` — false-positive trap). Perflogs live in the workspace (`tools/abtest/logs/`) — sandboxed shells block the engine's `/tmp` writes and `r_perflog` then fails silently. Stats: median + p95 of total frame, CPU render window (`r` = classic RenderView: traversal + batch + issue), GPU 3D window (`fin` = finish/present fence wait) via `parse_perflog.py --warmup 350 --window 2100` (350 tics = 10 s warmup discarded, 2100 tics = 60 s window).

**Results: 52/52 PASS.** First pass 24 PASS + 28 FAIL (the four non-commercial WADs are PWADs — fixed by the mount, all 28 re-runs passed). Full per-map medians (ms/frame, gl33/vulkan): `tools/abtest/results/baseline.md` (prose + table) and `results/baseline.json` (p95 + full per-field breakdowns) — the table is NOT reproduced here.

**Observations anchoring §9's bars.** (1) Vulkan's CPU RenderView window ≈ 2× GL33's on every map (0.05–0.33 ms vs 0.025–0.20 ms) while GPU 3d-fin is within ~0.1 ms — the Vulkan gap is on the CPU submission side at these scene sizes, not the GPU. (2) Total frame flat 0.3–0.6 ms across most maps; heaviest: **myhouse MAP01 0.82/0.99 ms** (35,853 sectors, portals) and **planisf 0.57/0.66 ms** (37,265 lines; p95 spikes to 6.1/7.1 ms). (3) These classic medians anchor the bars: levelmesh ≤ classic × 1.05 per map, both backends; SOS_Boom ≤ 50% of its classic median.

**L-line pin cross-check (all confirmed; a mismatch blocks the results).** Each perflog's `L` line (per-level summary: map, sectors, lines, subsectors, sprites, polyobjs, line portals, portal groups, 3D floors — keyed on `Level->MapName` after fix a06b0e2, so every reload emits it) checked against `manifest.md` pins + the static scanner: DOOM2/HERETIC/SOS_Boom/planisf2 no features as pinned; HEXEN polyobjs 12/7/9 active at load (vanilla format coverage); myhouse 20PAM line portals = 60 (exact pin match); myhouse MAP01 410 line portals (exact) + 89 portal groups vs 98 static `Sector_SetPortal` — **delta 9, flagged** — + 9,812 3D floors + 169 polyobjs, 165,922 lines; planisf2 37,265 lines / 6,287 sectors (exact); PIRATES 3D floors on all 7 maps (160–1759), portal groups on MAP50 (6) / MAP58 (3), **polyobjs = 0 at load on all 7** — the polyobject pin there is format coverage (start lines exist but nothing is active at level start: triggers need actors, `-nomonsters` is on, the synthetic camera need not cross them); active-polyobj render coverage comes from HEXEN (12/7/9) + myhouse MAP01 (169) instead.

## 3. Section 11 — references

- ADR `0001-levelmesh-full-parity.md` — the levelmesh path holds full parity with the classic path including `PORTAL` line specials and `sector_link`; "pragmatic parity" was rejected (it would fork the codebase and keep classic load-bearing), making portal rendering a first-class design problem and the acceptance bar correspondingly higher.
- ADR `0002-dynamic-geometry-vertex-warp.md` — moving/animated planes are not re-uploaded: the vertex shader warps the static mesh from a per-frame sector state buffer carrying single current CPU-interpolated plane values (no dynamic VBO, no GPU-side tick interpolation), making A/B parity on moving geometry exact by construction.
- ADR `0003-full-frame-sector-state-streaming.md` — the snapshot pass copies every sector state record into the current slot of a `HW_MAX_PIPELINE_BUFFERS`-slot ring every frame, no dirty tracking; small buffer + byte-identical-per-run keeps the A/B tool deterministic and trivially diffable.
- ADR `0004-ab-acceptance-policy.md` — zero-tolerance pixel diffing with exactly one structural exception: the frozen, human-reviewed, committed per-map known-diff allowlist, z-fighting only; new diffs fail; entries removable, never silently added (see §1 above for the rejection rationale).
- Research `01-helion-levelmesh.md` — deep dive into Helion's levelmesh pipeline (static per-texture VBOs, per-plane dynamic bitmask + prev/current dynamic VBO with GPU tick-fraction interpolation, per-sector GPU light buffer, GS sprite billboards, flood-fill + fake-wall + stencil portals), every claim cited to a Helion source file.
- Research `02-consumer-inventory.md` — file:line inventory of everything consuming the classic path's per-frame visibility results; proves the "render-only" assumption is broken in two places (per-frame automap/savegame flags, dither-transparency feedback loop) — basis for ticket 11 / spec §8.
- Research `03-portal-flow.md` — file:line documentation of how the classic BSP/HW renderer draws through `PORTAL` lines and sector_link/stacked-sector portal planes (data structures, per-frame registration, draw flow) — the levelmesh path's precise parity target.
- Baseline perf kit `tools/abtest/` — `README.md` (kit doc + protocol), `manifest.md` (pins, demo set, reference machine), `results/baseline.md` + `baseline.json` (the 52/52 classic baseline anchoring §10's bars) — see §4.
- **Distinction (spec §11, stated in full):** the perf kit EXISTS today (ticket 10 built and ran it; baseline results on disk); the in-engine A/B capture mode + external `tools/abtest.py` driver are BUILT by the implementation effort — do not conflate.
- Tickets: resolved tickets 01–11 live in `.scratch/levelmesh-rendering/issues/` under the wayfinder map `.scratch/levelmesh-rendering/map.md`; spec §3–10 map onto tickets 04–11.

## 6. Slices-relevant notes (sections 9–10 → future slices)

- The A/B tool slice should come FIRST: every later slice's verification (geometry, dynamic state, portals, lighting, draw paths, feedback) depends on a working classic-vs-classic comparator; the classic-vs-classic determinism run validates the tool itself (bit-identical on the same path) before any levelmesh work is measured against it.
- For the A/B tool slice to be self-sufficient it must deliver: the capture mode (synthetic clock + final-composed-framebuffer PNGs via the `M_ScreenShot` writer) + the `tools/abtest.py` driver (temp-autoexec config, same-backend pairs) + the committed manifest + the allowlist schema + the determinism proof (classic-vs-classic zero diff) + the reload-per-path run structure (monotonic exposure/dither state — a single session cannot host both paths).
- The perf-log cvar is a small, independent piece: the classic-side `r_perflog` already exists (ticket 10); only the levelmesh-side windows are new — needed only at the bars stage (PROVEN), cheap to land early or late, and the `parse_perflog.py --warmup 350 --window 2100` protocol + baseline numbers already exist to compare against.
