## 1. Section 7 — draw organization & backend paths (ticket 08, incl. amendments A1–A8)

**Render worker (Vulkan-only) — explicit spec-level deviation.** The levelmesh path adds a Vulkan-only render worker thread; the ticket's "fit into the render thread (`r_thread.cpp`)" premise was corrected as false (`r_thread.cpp/h` = software renderer's span drawer, never used by the HW path — "Locked by code investigation"). Helion master is synchronous single-threaded (primary-source check: `Client/Client.cs` `Window_MainLoop` → `RunLogic` → `Render` → swap; no render thread anywhere) — the user **chose async anyway**; deviation from both Helion and UZDoom's current state. The worker owns the **3D world pass only**: per-frame handoff-slot uploads (sector-state slot, 3D-light state, levelSkyPos, sprite/model vertex slots, window-poly buffer), the full 3D issue (pass order below, incl. occlusion-query issue) into the screen's render target, and a per-slot completion fence. It consumes frozen slot contents — **never playsim state**. The game thread keeps the sim, the frame build (inside the interpolation window), the 2D stack (ZWidget statusbar, menus, console, VM `CallDraw` — coupled to live game state, not a command list), and presentation; the fence wait lands where today's `RenderView` call happens (the `D_Render` lambda); `End2DAndUpdate()` untouched. **GL33 has NO worker** — 3D issues synchronously on the game thread; a shared second GL context for async is explicitly out of scope (GL calls are thread-bound to the context owner; Vulkan queue submission is thread-safe). What it buys: removes issue + upload CPU cost from the game-thread critical path (ring upload ≈ 4.8 MB/frame at 50k sectors, sprite/model vertex updates, descriptor updates, query issue, queue submit/driver stalls); today's Vulkan submissions are already async. Architectural precondition for deeper async later.

**Handoff slot — 05's sector-state ring IS the handoff ring.** No second ring. `HW_MAX_PIPELINE_BUFFERS` slots (2 desktop / 4 Android — `buffers.h:32/36`, same constant the existing per-frame `mBufferPipeline` buffers use). One slot = the per-frame frame record: sector-state records (05, 96 B/sector) + 3D-light state (07, 12 B/light) + levelSkyPos triple (07) + per-viewpoint values (camera pos/rot, fov, extralight, fog params — 07's per-view uniform list) + portal-view list (06: portal index, target region, view transform, query-gate flag, skybox/inkybox flag) + the **culled draw list** (main-region sub-range entries + per-portal-view entries) + sprite/model vertex slot references (the existing per-frame `mBufferPipeline` vertex ring — filled on the game thread as today) + the query results to apply (previous frame's). **Lifecycle:** game thread builds into the oldest free slot (blocks on the oldest in-flight slot's fence if none free — back-pressure); marks ready; signals the worker. Worker processes slots **in order** — **NO frame skipping**: the game thread 2D-composes per frame in order, so every built frame's 3D pass must complete; stale-frame drop is impossible in this architecture. Worker waits the slot's GPU-completion fence before reusing it, then uploads + records + submits. Desktop (2 slots) = 1 in build + 1 in flight (one frame of overlap — the maximum this architecture allows); Android (4) = two in flight.

**Frame build placement — inside the interpolation window.** The frame build REPLACES today's `RenderView` call in the `D_Render` lambda (`d_main.cpp`), so everything reading the single-buffered interpolated playsim state (sector planes, actor positions, light state, sky positions) runs on the game thread **between `DoInterpolations` and `RestoreInterpolations`**. Concrete game-thread sequence: (1) `DoInterpolations(I_GetTimeFrac())` (existing) → (2) snapshot pass (05: full sector-state copy into current ring slot, diff, lifecycle) → (3) per-portal transforms (06 step 2) + window-poly buffer update (GL33: game thread; Vulkan: worker derives from the slot) → (4) per-view sprite gather (main + query-gated portal views) → (5) dither tail (08, OOB non-portal views: `P_CheckSight` + `SetDitherTransFlags` — **the last playsim-mutating step**, A8) → (6) cull walk → compact per-slot culled draw list (+ 08's exposure marking + cullcolor latch) → (7) slot handoff: fill remaining fields (per-viewpoint values, portal-view list, light state, levelSkyPos, previous frame's query results with gate flags applied), mark ready, signal worker. Worker per slot (in order): wait fence → upload → record + submit full 3D pass in pass order (incl. occlusion-query issue for the predicted N+1 candidate set after the main-region pass; predicted N+1 camera = slot viewpoint + measured velocity × dt, computed by the worker from the slot's viewpoints) → completion fence. GL33: the same frame build, 3D pass synchronous in the `RenderView` call site's place (worker steps collapse into the game thread). 08's later async worker does NOT move the snapshot pass.

**Draw list & culling.** Sole draw source = the static per-region sub-range table — granularity **(region, texture, bandIndex)** (03's per-region IBO per-texture sub-ranges, 06's band split), built at load and **sorted by texture** (one material bind per (region, texture); band sub-ranges differ only by the `uBandIndex` uniform — no state change). Per-frame CPU walk on the game thread (interpolation window, **no per-frame allocation**): main-region table always walked; portal-region tables only for portals whose previous-frame occlusion query (06) passed. Each entry carries a precomputed **world AABB** → per-sub-range frustum test (thousands at slaughter scale ≈ trivial); a region early-outs if its own AABB misses. Output: compact per-slot culled draw list (sub-range index + vertex count; static bound = total sub-range count).

**Pass order — 1:1 with the classic `RenderScene`** (replaces the classic's geometry parts; same target, existing `FRenderState` state setters): ① main-region sub-ranges — z-buffered, depth write, DF_Less, STYLE_Source alpha cutoff (classic Parts 1+2+3 semantics: opaque, masked-cutoff, masked-OFS with the existing depth bias; 07's band-split draws live here) → ② models (existing `GLDL_MODELS` path with bones, unchanged; z-tested against levelmesh depth) → ③ decals (existing DF_LEqual path, unchanged) → ④ SSAO (unchanged; screen-space, `gl_ssao_portals` budget) → ⑤ portal views (06: stencil +1, depth clear, target-region sub-ranges under the view transform with the existing `mClipLine`/`mClipHeight` clip, nested recursion, per-view cull-mode flip for mirrored regions) → ⑥ `GLDL_TRANSLUCENTBORDER` + `GLDL_TRANSLUCENT` `DrawSorted` (depth mask off) — blended level surfaces + sprites → ⑦ occlusion-query issue for the next frame's predicted candidate set (after the main-region pass, depth-only window polys). **Order-independence argument:** opaque + alpha-cutoff (STYLE_Source, no blend) geometry is order-independent under the z-buffer — the classic's own `gl_sort_textures` re-sort (hw_drawinfo.cpp:547-551) of those lists is a batching optimization, not a visual mechanism; texture-grouped order is parity-safe for pass 1. **ONLY the blended pass is order-dependent** — the levelmesh feeds its blended surfaces (translucent 3D planes/flats — the small subset, at most dozens per map) into the classic's exact `GLDL_TRANSLUCENT` list as **per-surface entries** (a surface's pool span = one draw), reusing the classic's quadtree plane sort (`SortNode`/`FindSortPlane`, hw_drawlist.h:55-117) verbatim — sort algorithm, ordering semantics, depth-mask state all unchanged. No deviation, no parity waiver; A/B (09) gates at zero tolerance.

**Vulkan fit.** New pipeline layout = **HWBufferSet** (existing: per-viewpoint/matrix/stream UBOs + light/bone SSBOs — binds as today; the light buffer is genuinely used by `main.fp`'s dynamic lights; bones unused) + **LevelMeshSet** (new descriptor-set layout, one set per level: surface records 64 B/surface, sector-state ring as one large buffer of HW_MAX_PIPELINE_BUFFERS × level slots with slot selected by uniform, 3D-light state 12 B/light, static tables — band table, per-texture glow table, sub-range table + region records) + the **existing per-material texture set** (FTextureManager's Vulkan texture sets, reused as-is). New vertex format (04's 32 B, 6 attributes: pos3, dual-slot2, u, lightmapUV2, surfaceIndex) via `GetVertexFormat`; new pipeline (levelmesh VS + `main.fp` with 07's promoted-uniform adaptation block). Purely additive → no pipeline-cache invalidation (classic/raytracer/PP layouts untouched; new pipeline = new cache key). **Record buffers = UNIFORM TEXEL BUFFERS (`samplerBuffer`) on BOTH backends, locked by constraint:** GL 3.3 core has no SSBOs (SSBO = 4.3 core/ARB; the GL backend compiles 330-core, gl_shader.cpp:457-459) while `samplerBuffer` is core since GL 3.2 and native on Vulkan → one shared GLSL (`texelFetch` at integer texel = byte offset / 16; record sizes are 16-byte multiples: 64 B = 4 texels, 96 B = 6, 12 B → 16 B padded). A Vulkan-side SSBO variant is a 09/10 A/B perf item, not a design split. **Render passes: none new** — levelmesh draws into the existing scene render pass (same VkRenderPassKey: depth/stencil, MSAA, draw buffers).

**GL33 path.** One program (shared levelmesh VS + `main.fp` adaptation — same GLSL as Vulkan). Geometry: the vertex pool as **one VBO** (static; one upload at build; dynamic-surface spans re-uploaded on rebake — 05) + **ONE VAO PER REGION** capturing (VBO, region IBO, 6-attribute layout, stride 32); per draw = VAO bind + `glDrawElements` over the sub-range (region count small/static → trivial VAO count). Record buffers: uniform texel buffer objects per LevelMeshSet buffer (static upload + per-frame sub-uploads for sector state / light / sky — game thread, synchronous). State: existing `FRenderState` (depth test/mask, stencil for portal views, the existing `mClipLine`/`mClipHeight` VS uniforms for 06's view clip, cull-mode flip for mirrored regions); sector-state ring as per-slot buffers (HW_MAX_PIPELINE_BUFFERS), selected by uniform. Threading: game thread; shared second GL context out of scope.

**Sprites & models — no traversal.** Per frame, per active view (main + occlusion-gated portal views), walk that view's **region's actor list** (built at load: actors assigned to their subsector's region — 06's region partition), frustum-test each sprite vs that view's frustum (camera frustum for main; the portal's view-transform frustum for portal views — the classic's portal `DrawContents` sprite semantics), feed survivors into the **EXISTING sprite batch path** (HWSprite, `GLDL_TRANSLUCENT` entries, `DrawSorted` plane sort, OFS variants — all unchanged; per-sprite vertex fill on the game thread into the existing per-frame vertex ring as today). Sprites inside a portal view draw inside that view's stencil/clip, z-buffered against the portal view's geometry (06 step 6). The **visible-sprite list** this pass produces is section 8's input (the `RenderedTargets` replacement for the dither-transparency loop).

**Component fate** ("removed" = removed from the levelmesh path's frame, never deleted; the classic path stays fully intact):
- **Job pool stays classic-path-only** (`renderPool(1)` + `RenderJobQueue`, `gl_multithread`, hw_bsp.cpp:43-51, unchanged): it parallelizes per-frame wall/flat vertex generation (WallJob/FlatJob), which the levelmesh eliminates. The sprite gather is a per-view all-actor walk (~ns frustum tests) — single-threaded on the game thread.
- **Precache unchanged** (`hw_precache.cpp`, `gl_precache`): `PrecacheLevel` (p_setup.cpp) is already a renderer-independent WAD scan at level load; it warms the same textures the levelmesh binds.
- **Removed from the levelmesh frame:** `hw_bsp.cpp/h` (HWWalk/CreateScene traversal, job pool — the core cost), `hw_walls.cpp/h` (light chain → 07's VS), `hw_flats.cpp/h`, `hw_vertexbuilder.cpp/h` (replaced by 04's static pool build at build time + 05's rebake sub-uploads), `hw_portal.cpp/h` (replaced by 06's region/portal-view/query mechanism), `hw_clipper.cpp` (CPU BSP clipping → VS clip via the existing `mClipLine`/`mClipHeight`), `hw_sky.cpp/h` (replaced by build-time resolution + levelSkyPos, 07). `hw_drawinfo.cpp/h`'s CreateScene/RenderScene/DrawScene is replaced by the levelmesh frame build + 3D pass (new module), but DrawScene's shell shape (portal recursion, SSAO, 2D handoff) is preserved.
- **Kept:** `hw_drawlist.h` (HWDrawList / GLDL_*) for sprites + models + decals + blended level surfaces; `hw_precache.cpp`, `hw_shadowmap.cpp` (GPU ray tests against the play-sim-owned LevelAABBTree — traversal-independent, unchanged both paths), SSAO (`gl_ssao_portals`, screen-space, no level-geometry dependency), post-process. `r_thread.cpp/h` = SW renderer residue, unrelated to the HW levelmesh.
- **New:** levelmesh draw module (frame build + worker + 3D pass + queries), levelmesh VS + `main.fp` adaptation, LevelMeshSet/VAO/record-buffer wrappers, `gl_uselevelmesh` cvar + SettingsPage entry.

**Occlusion query plumbing (implements 06's deferred backend piece).** Per-level **pool of one query object per portal** (allocated at level load, sized to the portal count; released at teardown). Vulkan: **VK_QUERY_OCCLUSION** pool (pass count, not binary — the count is free and useful for A/B tooling/debug) + per-frame result buffer. GL33: depth-pass query objects (depth-only draw, no-op FS, no color write). **Window-poly buffer:** small **DYNAMIC** vertex buffer, one quad per portal (two triangles), updated per frame during the portal-transform step — static endpoints (06) + **current** heights of both portal-adjacent sectors (the same heights 06's transforms read; Vulkan: worker derives from the slot's sector state + portal transforms; GL33: game thread). **Timing:** frame N, after the main-region pass — update the window-poly buffer, issue the depth-only draw for the **predicted N+1 candidate set** (portals in the generous frustum of the predicted N+1 camera = slot viewpoint + measured velocity × dt, computed by the worker from the slot's viewpoints), begin the queries. Frame N+1 start: read frame N's results (complete — no stall; the one-frame staleness is inherent to 06's design) and apply the gate flags to the slot's portal-view list. GL33: same sequence on the game thread. The query gates both the portal view's draw **and** its depth clear (no clear → no spurious un-occlude).

**Selection.** `gl_uselevelmesh` (Bool, `CVAR_ARCHIVE | CVAR_GLOBALCONFIG`, **DEFAULT FALSE at handoff**). Read at level setup → picks the path per map; a mid-game toggle applies at the next map load (same semantics as backend switching); the A/B tool (09) drives the same cvar. **SettingsPage entry** (the LauncherWindow page — used at startup and as the in-game options menu — next to the backend radio group): checkbox/radio bound to the cvar; the page currently writes startup defaults via `FStartupSelectionInfo`, the entry additionally writes the cvar live for in-game use. The **default flip** (levelmesh becomes the default) is 09/10's call — it ships with the PROVEN declaration (09).

### Amendments A1–A8 (post-resolution, ticket 11, 2026-10-04)

- **A1 — Suplex-pitch-window cull for OOB non-radar views.** OOB views without `r_radarclipper` (or `LEVEL3_NOFOGOFWAR`) must cull with the classic's expanded vertical window — **pitch ± (20 + ½FOV), capped at 179°** (classic `hw_drawinfo.cpp:490-496`) — not the exact frustum. Their culled lists ARE the exposure candidate sets (08), so the expanded bounds apply to the list itself, not a side pass. (Reason: OOB traversal feeds no occluder ranges to the standard clipper at all, so an exact-frustum list would under-expose.)
- **A2 — OOB radar gate in the cull walk.** When `r_radarclipper && !LEVEL3_NOFOGOFWAR && bDoOob`, each candidate subsector fails the walk unless its radar gate passes (classic `hw_bsp.cpp:800-868`): already-exposed subsectors pass in non-deathmatch; otherwise the subsector is radar-ray-tested (08's BSP raycast, radar solidness, origin = `Viewpoint.OffPos`). A failing subsector is **NOT DRAWN** — the radar gate culls the draw too, not just exposure. Deathmatch: every subsector re-tested per frame (no already-exposed fast path).
- **A3 — Ortho no-fog views: viewbox cull.** `bDoOrtho && (!r_radarclipper || LEVEL3_NOFOGOFWAR)`: the walk tests subsector bboxes against the 2D viewbox (`ext = 3 · offset · tan(½FOV)`, classic `RenderOrthoNoFog`, `hw_bsp.cpp:1057-1075`) instead of the frustum.
- **A4 — Secret render gate.** OOB views without `r_radarclipper` exclude undiscovered-secret sectors' subsectors from the culled list (`hw_bsp.cpp:797`) and things inside them from the visible-sprite list (`hw_bsp.cpp:637`). Normal views are un-gated (the automap's secret DISPLAY gating is shared `am_` code — unchanged).
- **A5 — Static line→sub-range table.** At build, per line (and per flat plane / 3D-floor plane): the sub-range(s) containing it, the index range per sub-range, and the per-line **segCount within each sub-range** (the dither `dithertranscount` decrement unit — 08). Plus per-seg **map-exempt bit** (same-sector 2s line with an invalid mid texture) and per-subsector `hasSidedefSegs` bit (build-time). Together the table feeds the dither fragments, the `dithertranscount` decrement, and the exposure nuance.
- **A6 — `DITHERTRANS` pipeline-variant dimension.** The levelmesh pipeline key set gains the dither bit: dither fragments (08) draw the same sub-range index range with the `EFF_DITHERTRANS` / `main.fp #define DITHERTRANS` shader (adapted per 07's promoted-uniform variant).
- **A7 — Dither target source.** The per-view visible-sprite list (08's sprite gather output) is the dither target source: filter by `CurrentMapSections` + the A4 secret gate + eligibility `(MF3_ISMONSTER && !MF_CORPSE) || MF_MISSILE` + per-frame dedup; sort by `thing->subsector` index ascending (classic traversal order — exact in OOB mode, because the OOB traversal has no pruning); **cap 20** (`MAXDITHERACTORS`).
- **A8 — Frame-build order per view** (game thread, interpolation window): sprite gather → **dither tail** (08: `P_CheckSight` + `SetDitherTransFlags`, OOB non-portal views) → cull walk (dither fragment splitting + exposure marking + `cullcolor`, 08) → slot handoff. The tail precedes the walk (same-frame dither consumption — classic tail → RenderScene order) and is the **last playsim-mutating step** of view build; the worker never touches `validcount`-keyed memos.

## 2. Section 8 — per-frame game-logic feedback (ticket 11)

**Scope.** The two per-frame game-logic contracts ticket 02's consumer inventory proved the levelmesh path must replicate: the **exposure flags** — `SSECMF_DRAWN` subsector mark + `ML_MAPPED` line mark — read by the automap (`am_map.cpp:2103,2240,2692,3074,3359`) and serialized into savegames (`p_saveg.cpp:347-440`); and the **dither-transparency loop** (visible actor → `P_CheckSight` → trace-based `WALLF_DITHERTRANS_*` writes consumed by the same frame's drawing). Decisions: exposure = per-frame per-view **CANDIDATE LOS PASS** (D1, user-chosen over a full occlusion pass replicating the classic clipper and over pure frustum piggyback); dither = **FULL PORT now** (D2, user-chosen), gated behind the off-by-default `r_dithertransparency` cvar; `Level->cullcolor` reproduced from the culled draw list (D3); test points = all fan vertices (D4); ray mechanism = new BSP raycast over the glnodes tree (D5); the cullcolor gate is **frustum-only, omitting the classic's occlusion gate — one documented delta (D6)**.

**Exposure pass = per-frame per-view candidate LOS pass.** Per frame, per view, in classic view order (main → offscreen → portal views). Candidates (per view mode): normal (`!bDoOob`) = subsectors in the view's culled draw list (exact frustum); OOB non-radar (`!r_radarclipper || LEVEL3_NOFOGOFWAR`) = subsectors in the culled list computed with the **suplex pitch window** (A1 — the expanded bounds apply to the list itself); OOB radar = culled list where the radar gate also culls (A2); ortho no-fog = viewbox-culled list (A3). **Per candidate subsector S** (only while `!(S->flags & SSECMF_DRAWN)`): (1) OOB secret gate — `bDoOob && !r_radarclipper && S->sector` is an undiscovered secret (`isSecret() && wasSecret()`) → skip (no draw, no exposure — A4); (2) mode test — OOB non-radar: **PIGGYBACK mark** (no ray test) except when S has **no seg with a sidedef** (precomputed `hasSidedefSegs` bit — the classic's 1s-only-subsector nuance); OOB radar: radar gate = radar ray test over all fan vertices (radar solidness, origin = `Viewpoint.OffPos`), pass → mark, fail → S also removed from this frame's draw list (radar-gated rendering); deathmatch re-tests ALL (no fast path); normal: standard ray test over all fan vertices (standard solidness, origin = `Viewpoint.Pos`); (3) on mark: `S->flags |= SSECMF_DRAWN`, and for each seg of S with a linedef that is **not map-exempt** (precomputed per seg: same-sector 2s line with an invalid mid texture) → `linedef->flags |= ML_MAPPED`. **Marks are MONOTONIC** — once exposed, never re-tested, never cleared; re-testing of still-occluded candidates runs every frame (deterministic, frame-rate independent for a given camera path — the classic re-tests per frame too). **Test points (D4):** all distinct vertices of the subsector's seg fan (typically 3–6), precomputed at build — best coverage of the fan's angular extent (the classic marks when the subsector's full angular range is not covered by a *single* occluder; more points approximate that rule more closely), and the levelmesh's static data already carries the fan vertices — no extra structure. **BSP raycast (new levelmesh utility, D5):** input = 2D origin, 2D test point, solidness mode (standard/radar). Walk the glnodes tree: at each node determine which side the segment lies on / whether it crosses the node's split line; on a segment-vs-node-seg intersection test the solidness predicate; solid → return BLOCKED, non-solid → continue (the ray passes through, exactly as non-solid lines add no clip range in the classic). Track the sector on the origin side of each hit for the 2s fake-flat evaluation. **Solidness predicates** (classic sources, evaluated at *current* plane heights): standard — 1s or `WALLF_BLOCKRENDERING` → solid, unless `WALLF_DITHERTRANS_MID`; 2s: polyobject → never; same sector → map-exempt if the mid texture is invalid (ray passes); different sector → solid iff `hw_CheckClip(sidedef, currentsector, hw_FakeFlat(backsector, ...))`, unless `WALLF_DITHERTRANS_MID`. Radar — 1s → always solid (no height check, no dither exclusion); 2s: polyobject → never; else solid iff `hw_CheckClip(...)` (the classic's radar padding angle is a range-coverage detail irrelevant to a ray test — documented, negligible). Reuses the existing `hw_CheckClip`/`hw_FakeFlat` height evaluators directly. Deterministic: static tree and seg order; the only per-frame inputs are the origin and the predicate heights. O(tree depth + hits) — chosen over reusing the classic line-walk trace (unbounded cost on dense line layouts).

**cullcolor (D3).** Written **per frame per view from the culled list's segs**, in view order: for each seg with a sidedef in the culled list, `r_distance_cull_type > 0 && IsDistanceCulled(seg) && frontsector->Colormap.FadeColor != 0` → `Level->cullcolor = FadeColor` (classic latch `hw_bsp.cpp:378-392`). Latching semantics unchanged: no per-frame reset; `gl_cullcolor` initialization unchanged. **The occlusion gate is OMITTED** (frustum-only — documented delta D6: a culled line behind a wall can set the color; the value latches per level, so the effect is transient). Consumers (06): the view clear color + the fog color when `r_distance_cull_type > 1`.

**Dither transparency = FULL PORT (user-chosen, D2).** Per OOB non-portal view (main or offscreen) — gate: `r_dithertransparency && doOob && RTnum < MAXDITHERACTORS && mCurrentPortal == nullptr` (`MAXDITHERACTORS = 20`): (1) **Target collection** from 08's **VISIBLE-SPRITE LIST** (A7): filter by `CurrentMapSections[thing->subsector->mapsection]` + the OOB secret gate (`!r_radarclipper`: things in undiscovered secrets excluded — classic `hw_bsp.cpp:637`) + eligibility **monster-not-corpse ‖ missile** (`(MF3_ISMONSTER && !MF_CORPSE) || MF_MISSILE`) + per-frame dedup (`thing->validcount`); sort by `thing->subsector` index ascending (**= the classic's traversal order — exact, because the OOB traversal has no pruning**); **CAP 20**. (2) **The CLASSIC TAIL VERBATIM:** per target, `P_CheckSight(players[consoleplayer].mo, target, 0)` (keep the player-pawn asymmetry — sight from the **console player's pawn**, not the camera) → `SetDitherTransFlags(target)` — the classic method verbatim (`hw_drawinfo.cpp:815`): 6 traces, `TRACE_PortalRestrict`, mapsection gate, tier/count rules, own-sector 3D-floor flags, ortho variant. (3) **Flag storage = the classic's playsim storage — NO new GPU state:** `FLineSide::Flags` (`WALLF_DITHERTRANS_TOP/MID/BOTTOM`) + `FLineSide::dithertranscount`, `plane_t::dithertransflag`, `F3DFloor` plane flags; the dither effect is a shader variant, not data. (4) **Consumption (during the cull walk, per view):** for each surface (wall tier / flat plane / 3D-floor plane) whose flag is set and whose sub-range is in this frame's list, append a **dither fragment** — the same sub-range index range drawn with the `DITHERTRANS` pipeline variant (A6; the existing `EFF_DITHERTRANS` / `main.fp #define DITHERTRANS` shader adapted per 07) — then consume: TOP/BOTTOM flags cleared; MID: `dithertranscount -= segcount(line, sub-range)` (precomputed — A5's static line→sub-range table — replicating the classic's per-seg decrement), flag cleared at 0; flat/3D-floor: `dithertransflag` cleared. **UNSEEN SURFACES KEEP RESIDUE** — surfaces not in this frame's list keep their flags (the classic's clear-on-consume semantics). **Same-frame consumption holds:** flags written by the dither tail (frame-build step 5) are consumed by the cull walk (step 6) of the same frame, exactly the classic's tail → RenderScene order.

**Frame timeline (game thread, inside the interpolation window), views in classic view order:** (1) snapshot pass (05, once) → (2) sprite gather for the view → visible-sprite list (08) → (3) dither tail (OOB non-portal views only): target collection + `P_CheckSight` + `SetDitherTransFlags` — writes flags for this frame → (4) cull walk → culled draw list, during which: dither fragment splitting (reads step 3's flags + last frame's residue), exposure marking, cullcolor computation → (5) slot handoff: the portal-view list is filled with the previous frame's query gate flags; the worker then issues the 3D frame, including the occlusion-query prediction + issue for the next frame. Ordering constraint (A8): the dither tail precedes the cull walk and is the last playsim-mutating step — `P_CheckSight`/`Trace` touch `validcount`-keyed memos; nothing in the view after it, and nothing in the worker, may depend on those memos.

**Savegame round-trip.** No change: the flags live on `subsector_t`/`line_t`, the levelmesh writes the same fields, and `p_saveg.cpp:347-440` (incl. the `SSECMF_DRAWN`-from-`ML_MAPPED` recovery path) is shared code. **A/B note:** exposure and dither state are **MONOTONIC GAME STATE** — an A/B comparison of frames exhibiting these effects must **RELOAD THE LEVEL PER PATH** (both paths start from the same fresh state); alternating paths on a live level cross-contaminates the flags. (The 09 run structure already mandates two fresh-level-load launches per map × mode × backend.)

**Acceptance checks (feed 09).** (1) **Exposure parity (default cvars):** scripted camera walk; compare per-subsector `SSECMF_DRAWN` + per-line `ML_MAPPED` between classic and levelmesh at matched tick/camera state — target identical sets; any diff must be classified as an approved candidate-approximation delta (a subsector whose full range is covered by no single occluder, but whose fan vertices are each blocked by different lines) or a bug; strong proxy = savegame byte-diff of the flag sections after the same scripted walk.
