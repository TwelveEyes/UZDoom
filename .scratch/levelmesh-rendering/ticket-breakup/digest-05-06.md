# Digest 05–06 — levelmesh spec §5–§6 (portal & sector_link rendering, lighting & visual effects)

Grounded against the codebase verified in this task (§3 below). Ticket map: spec §5 ↔ ticket 06, §6 ↔ ticket 07. ADR 0001 governs §5: full portal parity; Helion's flood-fill + fake-wall approach is REJECTED as the parity path — the levelmesh instead re-partitions the level statically and re-draws target regions under remapped views.

## 1. Section 5 — portal & sector_link rendering (ticket 06)

**Region model (static, build-time).**
- **Global flood-fill over the sector graph** (runs at §3 build-order step 3 "Assign regions"): two sectors adjacent iff they share a two-sided line that is NOT a portal; portal lines are barriers; one-sided lines never connect; each connected component = one region.
- **Main region** = the component containing the player's start; all other components = **portal regions**.
- **Portal targets fixed at build**: line portal → the region *behind* its destination line; `sector_link` → the region of its destination sector.
- **View scoping**: the main view draws only the main region; each portal view draws its target region + nested sub-views. The portal line's **window wall stays in the main region** (it is the visible frame). **Fake flats / 3D floors / `sector_link` destinations need no special mechanism** — extra surfaces referencing their model sector, sitting in the subsector's own region. **Re-bake stays per region** and is shared across every view that draws that region (no per-portal copies).

**Region record slots (semantics of §3's container).**
- **`transform` — remapped viewpoint.** Main region: identity. Line portal: rotation by the portal angle diff + translation to the destination line + a **z-rebase**; the rotation/translation/angle terms derive from the portal line pair (build time), the z-rebase is taken from **current** sector heights and evaluated **at runtime** (heights move; parity because `DoInterpolations` writes tick-blended heights before render, §4). `sector_link`: pure displacement. **Nested portal views COMPOSE** (parent ∘ child); sky/skybox use the same composed-transform mechanism. The per-frame evaluated values (z-rebases, composed transforms, one per visible view) are the per-frame view state §7 streams; §5 locks semantics only.
- **`frontFace` CCW | CW.** CCW for the main region and views whose composed transform has positive determinant. **Negative determinant = mirrored** → the view MUST draw its target region with **frontFace = CW**. The face follows the *drawing view's* composed transform (a region targeted by several portals is drawn with the face of the view actually drawing it); the record slot carries the region's default (unmirrored) value.
- **`texRangeOffset`/`texRangeCount` — per-texture sub-range table.** The region's static draw table, built at load, **the SOLE draw source of the levelmesh path** (§7): one entry per **(region, texture, bandIndex)** — (region, texture) is band 0; further entries are §6's band splits (sub-range k = quads of walls having ≥ k+1 bands, pool order, re-referencing the same vertex pool). **Sorted by texture** within the region (one material bind per (region, texture); band sub-ranges in a group differ only by the `uBandIndex` uniform). Entry = contiguous IBO range `{ textureIndex, iboOffset, iboCount }` + a **precomputed world AABB** for §7's cull walk. Walked per frame when a view drawing the region is active — **main region always; a portal region only if its previous-frame occlusion query passed**.
- **Scissor/stencil.** Stencil level = the portal's nesting depth (nested portal draws inside its parent's view at level +1 with the composed transform); the level, with the view's scissor clip, masks the portal's sub-range draw and its interior depth clear to the **window polygon** (per-frame sequence step 5). Main region draws at level 0.

**Per-portal view transform — one shared mechanism.** A portal view = a per-portal view transform + **view clip** applied to the target region's per-texture IBO sub-ranges (§3). No per-portal mesh baking, no per-portal vertex copies (one whole-level pool). Line portals: rotate + translate + angle + z-rebase from current heights (runtime). `sector_link`: pure displacement. Nested compose (parent ∘ child). **View clip = the destination line/plane.** **Sky / skybox are INSTANCES of this mechanism** — 06 locks the mechanism; 07 owns sky texturing/effects.

**Visibility — GPU occlusion query, 1-frame-ahead prefetch.**
- **Query**: per-portal **depth-only draw of the window polygon** (under the main view) with a depth-pass query; result > 0 = visible.
- **1-frame-ahead prefetch**: queries issued in frame N (after the main pass, tested against the main region's depth) gate frame N+1's portal draws — inherently one frame stale.
- **Candidate set = PREDICTED set**: frame N+1 camera = current camera + measured per-frame camera velocity × dt; candidates = portals inside the **predicted frustum** (generous margin / widened FOV).
- **Miss**: a portal the prediction misses appears once it enters the candidate set and its query passes — a bounded 1–2 frame delay, accepted.
- **Gating**: the query gates BOTH the portal draw and its depth clear (no clear → no spurious un-occlude).
- **Deferred to §7**: the query objects (Vulkan occlusion pool vs GL33 depth-pass query) and the window-poly buffer plumbing; §5 locks the protocol only.

**Recursion / re-entry.** The classic caps are preserved (max portal nesting depth, max portals per frame) **plus a per-frame visited-set** against cycles. **Draw order**: main pass first, then portals in **LIFO / registration order**; a nested portal draws inside its parent's view (stencil +1, composed transform).

**Per-frame portal render sequence (locked, runs in §7's frame build, inside the interpolation window).**
1. `DoInterpolations` → snapshot pass (§4).
2. Per-portal transforms (line: rotate/translate/angle + z-rebase from current heights; `sector_link`: displacement).
3. Draw the main region (all main-region × texture IBO sub-ranges, main view, z-buffered) — fills the depth buffer.
4. Issue occlusion queries for the predicted candidate set (depth-only window-polygon draw, main view) — gates the *next* frame.
5. For each portal visible per last frame's query (LIFO / registration order; recursion + visited-set): **stencil increment on the polygon → clear depth inside** (depth-buffer portals only; sky/skybox need none) → **draw the target region's sub-ranges under the composed view transform + view clip (destination line/plane), stencil-masked** → recurse nested sub-views → **stencil decrement + depth restore**.
6. Sprites (§7), z-buffered against the levelmesh.

**Handoffs — what §5 owes.**
- → §3: §3 consumes §5's region partition (build-order step 3) and the `transform`/`frontFace`/scissor-stencil semantics this section fills; mirrored portal regions set `frontFace = CW`; the per-region re-bake is shared across every view drawing the region.
- → §4: the snapshot-pass ordering (after `DoInterpolations`) is what makes step 2's current-height sampling match the classic per-frame behaviour; no state mechanism is needed for fake flats / 3D floors / `sector_link` destinations (surfaces sample their referenced model sector's record).
- → §6: sky and skybox are instances of the portal-view mechanism locked here; 07 owns sky texturing/effects and composes the skybox view with the sky's own transform.
- → §7: §7 implements the deferred backend pieces (occlusion query objects, window-poly buffer plumbing) and streams the per-frame view state (per-portal composed transform, `frontFace`, scissor/stencil) step 5 consumes; a draw = one (region, texture, bandIndex) sub-range.

## 2. Section 6 — lighting & visual effects (ticket 07)

**Shading model (round 1).** The classic per-surface light chain (effective light → RescaleLightLevel → CalcRelLight → CalcLightLevel → CalcLightColor → vColor + softlight/fog/desat/glow) runs **IN THE LEVELMESH VERTEX SHADER** as a formula-for-formula **BIT-EXACT GLSL port**: int32 on the integer paths; the C++ op order in float32 on the float paths; the fake-contrast rel is **baked CPU-side at build — no GPU atan**. Why the CPU cannot pre-compute: a levelmesh draw is a (region, texture, bandIndex) sub-range spanning many sectors and sides — the classic's per-draw `SetColor`/`SetFog` state has nowhere to live; every per-surface input is either per-sector-per-frame (light thinkers, fire/pulse/damage colormaps) or per-surface-static (side tier lights, fake contrast) — exactly the two sources the VS already fetches (§4 state record, §3 surface record). **Fragment = the existing `main.fp` + a define-level adaptation** promoting the per-draw light/fog/glow/desat values to per-vertex varyings (≈12 vec4, inside GL33 limits); all per-pixel math in `main.fp` (Doom lighting equation, fog, glow falloff, lightmaps, dynamic lights) is untouched. C++ remains the single source of truth for the equations; A/B (zero tolerance) is the gate.

**Port list (C++ reference → levelmesh VS), classic order.**
1. Flat effective light: `sector_t::GetFloorLight`/`GetCeilingLight` (p_sectors.cpp) — `ABSLIGHTING ? planeLight : hw_ClampLight(lightlevel + planeLight)`; the lighting sector is the one the surface's `lightRef` (§3) points at (transfer-light / heightsec semantics).
2. Wall base light: `side_t::GetLightLevel` (p_sectors.cpp:1579) — ABSLIGHTING global/tier branches; fake-contrast `rel` computed and *returned separately*; trailing `Light + TierLights[which]` add gated on `!is3dlight && !ABSLIGHTING && !TIERABS && (!foggy || LIGHT_FOG)`; `foggy = (frontsector->Colormap.FadeColor != 0) || (Level->flags & LEVEL_HASFADETABLE)`.
3. `CalcRelLight` (hw_walls.cpp:2100) — the 3-branch rel → rellight (org ≥ 253 → 0; lightlevel − rel > 256 → 256 − lightlevel + rel; else rel).
4. `RescaleLightLevel` (hw_lighting.h:35) — the r_extralight cvar.
5. Weapon/extra light: `getExtraLight` (hw_lighting.h:51) = `r_viewpoint.extralight * gl_weaponlight`; flats add it as the whole rel; walls add it to the fake-contrast rel (hw_walls.cpp:208 `int rel = rellight + getExtraLight()`).
6. `CalcLightLevel` (hw_lighting.cpp) — the ELightMode branches (dark-mode integer path incl. the 1.87f product + RoundHalfEven and the 20-clamp; the software-lighting path) → the uLightLevel value.
7. `CalcLightColor` (hw_lighting.cpp) — integer colormap math (LightColor/BlendFactor/Desaturation) → vColor.
8. `GetFogDensity` + `SetFog`/`SetShaderLight` (hw_setcolor.cpp:59,93) — distfogtable (256×2 f32 uniform buffer, rebuilt on `gl_distfog` change), MAXDIST = 32·r_visibility, the cullcolor branch (`r_distance_cull_type > 1`), outsidefog, fullbright, gl_fogmode.
9. uFogEnabled encoding (vk_renderstate.cpp:356-372): 0 = no fog; black fogcolor → +gl_fogmode (1 = view-depth fade, 2 = true distance); non-black → −gl_fogmode. Levelmesh: computed per vertex into vFogEnabled; the main.fp branches already key off it.
10. The 3D-light variants (band split / FF_FOG — below).

`ELightMode` is per level (`Level->info->lightmode`, `gl_maplightmode`, `gl_lightmode` → `getRealLightmode`, g_level.cpp:151) → **per-level uniform**; `uPalLightLevels`/numShades → **global** uniforms.

**Contract details.** The levelmesh VS computes the full chain per vertex and emits: all `main.vp` varyings (vColor, vTexCoord, vLightmap, vWorldNormal, vEyeNormal, pixelpos, glowdist, gradientdist) **plus the promoted per-surface values**: vLightLevel, vFogDensity, vLightFactor, vLightDist, vDesaturation, vFogEnabled (int), vGlowTopPlane, vGlowBottomPlane, vGlowTopColor, vGlowBottomColor — ≈45 float units ≈ 12 vec4. **EVERY surface fetches the sector state record for shading — not only dynamic ones** (light thinkers — strobe/pulse/fire/glow — mutate arbitrary sectors without moving geometry). For a dynamic surface the same fetch serves the warp. Bandwidth: 96 B/vertex, L1/L2-resident (50k sectors ≈ 4.8 MB), good locality from the per-region/per-piece pool order; §9/10 validate at scale.

**The two record amendments (07's, both user-approved).**
- **Sector-record light re-slot (amends §4):** the 96 B record's light slots become **RAW INGREDIENTS** — `lightlevel` (raw `sector->lightlevel` 0..255) + `planeLight[2]` (secplane Light offsets) + the 9-byte `FColormap` (LightColor/BlendFactor/Desat/FadeColor/FogDensity) + per-plane ABSLIGHTING bits — the VS derives the effective light. 05's `colormap` uint32 was annotated "selfmap" — **wrong: SW-only, the HW path never reads `selfmap`**; 05's `skyOffset` slot is **reserved** (round-3 sky split). Amended in place in §4; size unchanged.
- **Surface-record growth 48 → 64 B (amends §3):** 04's documented offsets had an 8-byte hole (`planeRef[4]` spans 8..24 but `lightRef` was listed at 32); 07 normalizes the base layout and appends a 16-byte wall-shading/sky block (side `Light`/`TierLights[tier]`, baked rel pair, `lightlistRef`, band refs, extended flag bits incl. tier, lightmapNum, skyScrollKind, m2snf). The final layout is in §3.

**Fake-contrast bake.** `rel = f(line delta, Level->WallHorizLight, Level->WallVertLight)` is static — smooth: `RoundHalfUp(WallHorizLight + fabs(atan(dy/dx)) / 1.57079 * (Vert − Horiz))` (delta.X != 0); classic: delta.X == 0 → Vert, delta.Y == 0 → Horiz, else 0 (p_sectors.cpp:1579). **Both values are baked CPU-side at build** into the surface record's `relSmooth`/`relNonSmooth` — no GPU atan. VS: `smooth = LEVEL2_SMOOTHLIGHTING || side smooth || r_fakecontrast == 2`; rel applies only when `(!foggy || LEVEL3_FORCEFAKECONTRAST) && !NOFAKECONTRAST && r_fakecontrast != 0`; rellight = `CalcRelLight(L, org, rel)` with **org = the raw (unrescaled) frontsector lightlevel**.

**3D floor lights (round 2).**
- **Light state buffer** (per level, full-copied per frame like §4's): one **12 B record** per lightlist entry — `uint16 lightlevel` (raw `*p_lightlevel`), `FColormap` 9 B (the light's `extra_colormap`, re-copied at runtime by `P_RecalculateLights`), 1 B pad. **LIVE values** (pointers into source sectors; A_ChangeSector colormap propagation) — nothing baked.
- **3D-floor flats:** `lightlistRef` baked at build (`P_GetPlaneLight` resolution is static topology) → VS: `L = RescaleLightLevel(light.lightlevel)`; colormap = the light's (FF_FOG flag: LightColor := light.FadeColor, other components 0, white FlatColor — hw_flats.cpp `SetFrom3DFloor`). Flats do not split.
- **Walls in a 3D volume = PER-BAND SUB-DRAWS** (the classic splits them, hw_walls.cpp:305-325): the wall quad is drawn once per intersecting 3D-floor layer, each clipped to that layer's z-band via `uSplitTopPlane`/`uSplitBottomPlane` (main.vp:79-82 clip distances; the planes = the 3D-floor plane + next-layer plane / front floor — dynamic, from the sector state records).
- **Build time:** enumerate the intersecting 3D-floor layers per wall (static structure) → **M band records** in a per-level static **band table**: `{ int16 lightRef; int16 reserved; uint32 splitTopPlaneRef; uint32 splitBottomPlaneRef }` (**16 B**). Split refs are §3 plane refs into the model sectors; `lightRef = -1` → the band has no caster → use the wall's own light (the classic `caster == nullptr` case). The base surface record keeps the tier statics and points at its band range (`bandOffset`/`bandCount`).
- **IBO:** sub-range granularity = (region, texture, **bandIndex**) — §7 consumes. Sub-range k contains the quads of walls having ≥ k+1 bands, in pool order. The vertex pool is unchanged (bands re-reference the same quads; only IBO indices repeat).
- **VS (band k):** light = `band.lightRef >= 0 ? RescaleLightLevel(lightBuf[i].lightlevel) : the wall's normal chain`; colormap = the light's FColormap **with the wall's own FadeColor/FogDensity** (the classic merges `thiscm.FadeColor/FogDensity = Colormap.*`, hw_walls.cpp:315-317); split planes = the sector-record planes of splitTop/BottomPlaneRef → ClipDistance3/4 exactly as main.vp:81-82.

**Parity strategy (round 2).** Integer paths (CalcLightColor, RescaleLightLevel, CalcRelLight, the Doom-dark integer branch of CalcLightLevel, all clamps) use **int32 — bit-exact**. Float paths (the 1.87f dark-mode product + RoundHalfEven, GetFogDensity, the distfogtable f32 lookups, sky scroll adds) **replicate the C++ op order in float32** — bit-exact under IEEE-754 (both sides float32). distfogtable (256×2 f32) is a uniform buffer rebuilt on `gl_distfog` change; fake contrast is baked (no GPU atan); **skytransfer resolution happens at build**. Verification: A/B tool, **zero tolerance**, on the checklist + the cvar sweep.

**Sky: ordinary geometry (round 3).** Verified classic facts: sky is shaded like ordinary geometry (frontsector light + colormap; **no special light level**). The dynamic per-frame sky state is just three per-level floats (`hw_sky1pos`/`hw_sky2pos`/`hw_skymistpos`, r_sky.cpp:146, advanced by `R_UpdateSky`). `sector->skytransfer` is a **static int** (MBF: 0 or `(lineIndex+1) | PL_SKYFLAT` — texture from that line's sidedef: angle = texture X offset × 360/65536, y offset, mirror flag; resolved by `HWSkyInfo::init`, hw_sky.cpp:56).
- **Build:** sky surfaces (§3 flag bit 1) resolve at build time **exactly as `HWSkyInfo::init` does** (which sky texture — incl. the sky2/doublesky selection from LEVEL_SWAPSKIES/LEVEL_DOUBLESKY/PL_SKYFLAT and the MBF line-texture case) → the static parts (texture, angle offset, y offset, mirror) **fold into the pool's baked u/v + textureIndex**; the surface record carries `skyScrollKind`/`skyScrollKind2` (which of the three per-level scroll positions drives the surface; doublesky second layer).
- **VS:** `u += levelSkyPos[skyScrollKind]` (+ second layer for doublesky), with `levelSkyPos = (hw_sky1pos, hw_sky2pos, hw_skymistpos)` a **per-level per-frame uniform triple** — the locked round-3 split: **NO per-frame sector-record write for sky scroll** (§4's `skyOffset` slot is reserved; scrolling-sky levels churn zero record bytes).
- **Sky fadecolor rule** (hw_sky.cpp:116-126) as a VS branch on sky surfaces: `r_distance_cull_type > 1` → `FadeColor > 0 ? FadeColor : gl_cullcolor`; else `Level->skyfog > 0` → the sector FadeColor; else none.
- **Skybox** (PORTS_SKYVIEWPOINT/HORIZON/PLANE, GLSector_Skybox) = a **§5 portal view**: ordinary flat/wall shading inside, plus the inkybox fog-density ×1.5 boost and cullcolor as **per-view uniforms**.

## 5. Discrepancies

1. **"Max portals per frame" cap — spec §5 vs code.** §5 says the classic caps are preserved "(max portal nesting depth, max portals per frame)". No per-frame portal *count* cap exists in the code — registration is unbounded; only the nesting cap `r_portal_recursions` (default 4, `hw_cvars.cpp:45`) and the `renderdepth > 100` emergency abort (`hw_portal.cpp:823`) exist. The levelmesh "preserved cap" for portal count would be new, or the spec wording is aspirational.
2. **m2snf cite moved.** The §3 flag table (07 block) cites `hw_walls.cpp:291` for "fog runs at light 255 / rel 0"; the actual call is `hw_walls.cpp:239-240` (`SetFog(state, ..., 255, 0, ...)`); line 291 is the `RenderWall` in the non-split branch.
3. **Colormap-merge cite moved.** §6 cites `hw_walls.cpp:315-317` for the classic merge `thiscm.FadeColor/FogDensity = Colormap.*`; the assignments are at `:308-309` with `CopyFrom3DLight` at `:310` — 315-317 is the loop tail/`break`. (The 3D-split cite `hw_walls.cpp:305-325` is accurate as a range.)
4. **Port-list item 8 file attribution.** `GetFogDensity` is listed under the `(hw_setcolor.cpp:59,93)` cite, but it lives in `hw_lighting.cpp:159`; 59/93 are `SetShaderLight`/`SetFog`.
5. **`Level->lightlist` naming.** There is no per-level `lightlist` container; the 3D-light entries live per sector in `sector->e->XFloor.lightlist` (`TArray<lightlist_t>`, `p_3dfloors.cpp:307/596/640`). The 12 B per-frame light state buffer implies a level-wide enumeration (and possible dedup) of those per-sector entries at build.
6. **`uPalLightLevels` packing tension (note, not necessarily an error).** The spec classifies `uPalLightLevels`/numShades as *global* uniforms while `lightmode` becomes a *per-level* uniform; today `uPalLightLevels` is a single per-viewpoint packed int (`32 | fogmode<<8 | lightmode<<16`, or the `gl_bandedswlight` variant — `hw_drawinfo.cpp:162-167`, `hw_viewpointuniforms.h:42`). The implementer must re-derive the pack for the new layout.
